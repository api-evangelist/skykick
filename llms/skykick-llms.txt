# SkyKick

> SkyKick is a Seattle-based cloud automation company whose Microsoft 365 migration, cloud backup, SaaS security and cloud automation products for managed service providers were acquired by ConnectWise in September 2024. The products now ship as ConnectWise Cloud Backup and ConnectWise SaaS Security. The SkyKick Partner Integration API is still live on ConnectWise Cloud Services, but its reference documentation is gated behind a partner sign-in and no machine-readable contract is published.

This file is GENERATED by API Evangelist from an independent third-party profile of SkyKick's public API surface. It is not published by SkyKick or ConnectWise. Probed 2026-08-28. Provenance: https://apievangelist.com/about/where-our-data-comes-from

## API

- API: SkyKick Partner Integration API
- Base URL: https://apis.cloudservices.connectwise.com
- Style: REST over HTTPS, JSON, fronted by Azure API Management, ASP.NET Web API backend.
- Known path roots: /auth/token (token exchange), /whoami (identity), /Backup (backup resources).
- Machine-readable contract: NONE published. No OpenAPI, Swagger, GraphQL SDL, AsyncAPI, Protobuf or WSDL.
- Live proof the API exists: GET /whoami returns HTTP 401 with WWW-Authenticate: Bearer.

## Authentication

Two credentials are required on every call.

1. Azure API Management subscription key, sent as `Ocp-Apim-Subscription-Key`.
2. An OAuth 2.0 client-credentials bearer token.

Token request:

    POST https://apis.cloudservices.connectwise.com/auth/token
    Ocp-Apim-Subscription-Key: {subscription key}
    Authorization: Basic base64(ClientId:Secret)
    Content-Type: application/x-www-form-urlencoded

    grant_type=client_credentials&scope=Partner

Valid scopes: `Partner`, `Distributor`.

Credentials are not self-service. An administrator of an existing partner tenant must add a user with the Developer Access flag in the Cloud Services portal; the ClientId, Secret and subscription keys then appear under Admin > User Profile > Developer API Access.

## Error envelopes

Two distinct shapes are in use and they disagree on field casing.

- Gateway (unrouted path): `{ "statusCode": 404, "message": "Resource not found" }`
- Backend (authorization failure): `{"Message":"Authorization has been denied for this request."}`

Neither is RFC 9457 `application/problem+json`.

## What is NOT published

- No OpenAPI or any other machine-readable contract.
- No MCP server, hosted or local.
- No A2A agent card (`/.well-known/agent-card.json` and `/.well-known/agent.json` both 404 on all four hosts).
- No `/.well-known/` documents of any kind, including security.txt, openid-configuration and oauth-authorization-server (all 404).
- No first-party SDK, in any language, on any registry.
- No CLI, sandbox, embedded components or changelog.
- No published rate limits, pagination convention, idempotency guarantee or deprecation policy.
- No published pricing: the successor products are quote-only.
